# QuantumRoute AI

Hybrid quantum-classical route optimization for a curated Chandigarh transportation scenario. The application compares Dijkstra, A*, Bellman-Ford, and a QUBO candidate-selection experiment executed with QAOA on Qiskit Aer. It also trains and evaluates linear regression, random forest, and gradient boosting traffic models on a reproducible synthetic scenario dataset.

The product is deliberately explicit about evidence:

- QAOA runs on a local simulator, not quantum hardware.
- No quantum advantage or speedup is claimed.
- The Chandigarh graph uses real landmark coordinates with curated edge attributes; it is not a live or complete road feed.
- ML metrics come from a chronological holdout set generated by the labelled synthetic-data pipeline.
- Dashboard, history, comparison, analytics, and exports use stored executions rather than fabricated values.
- Route polylines are snapped to OpenStreetMap roads through OSRM; a clearly labelled waypoint fallback is used when OSRM is unavailable.

## Stack

- React 19, TypeScript, Vite, Tailwind, Leaflet, Recharts
- FastAPI, Pydantic, SQLAlchemy 2, Alembic, PostgreSQL
- OSRM Route API with full GeoJSON road geometry
- NetworkX classical routing with one normalized weighted objective
- Qiskit 1.1, Qiskit Aer, COBYLA, shot-based QAOA
- scikit-learn, pandas, NumPy

## MacBook Air M2 setup

The verified runtime is Python 3.12. Python 3.14 is not recommended for this Qiskit release.

### 1. Install prerequisites

```bash
brew install python@3.12 postgresql@17 node
brew services start postgresql@17
createdb quantumroute
```

If `createdb` reports that the database already exists, continue.

### 2. Configure and migrate the API

```bash
cd "/Users/puneetkumargarg/Documents/Capstone Codex/backend"
/opt/homebrew/bin/python3.12 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
cp .env.example .env
```

Generate a local signing secret and place its output in `SECRET_KEY` inside `backend/.env`:

```bash
openssl rand -hex 32
```

For the first launch only, set `INITIAL_ADMIN_EMAIL` and a strong `INITIAL_ADMIN_PASSWORD` in `.env`. Then apply migrations:

```bash
.venv/bin/alembic upgrade head
```

Start the API:

```bash
.venv/bin/uvicorn main:app --reload --port 8000
```

API documentation is available at [http://localhost:8000/docs](http://localhost:8000/docs), and health evidence at [http://localhost:8000/api/health](http://localhost:8000/api/health).

After the administrator has been created, remove `INITIAL_ADMIN_PASSWORD` from `.env`.

### 3. Start the web application

In a second terminal:

```bash
cd "/Users/puneetkumargarg/Documents/Capstone Codex/frontend"
npm ci
npm run dev
```

Open [http://localhost:5173](http://localhost:5173). Register a standard account from the UI or sign in with the administrator credentials you configured.

The first optimization is submitted with **Optimize Route**. After results exist, changing source, destination, vehicle, traffic density, weather, road condition, time, optimization priority, closure, or construction scenario automatically recomputes the route after a short debounce. QAOA depth, shots, and custom-weight changes remain explicit because they can be computationally expensive.

The **Route Decision Explanation** view identifies which controls changed and explains the result from segment-level width, speed, accessibility, traffic, weather, surface, construction, time, fuel, and objective evidence. It compares ranked alternatives and the previous route. If the path remains unchanged, it says that the route retained the lowest measured objective rather than inventing a route change.

Detailed implementation evidence and the PGI Hospital → Elante Mall validation are in [`IMPLEMENTATION_STATUS.md`](IMPLEMENTATION_STATUS.md).

## Architecture

```text
frontend/
  src/pages/                 product workflows and evidence views
  src/components/map/        Leaflet route/scenario rendering
  src/components/quantum/    QAOA evidence and fair comparison
  src/components/routes/     segment-level route-decision explanation
backend/
  routes/                    validated FastAPI contracts
  services/routing.py        shared cost function and classical solvers
  services/optimization.py   hybrid orchestration and recommendation
  services/osrm.py           cached road-geometry adapter with explicit fallback
  quantum/qubo.py            one-hot candidate QUBO and decoder
  quantum/engine.py          candidate generation and Aer QAOA
  quantum/qaoa_engine.py     curated Chandigarh scenario graph
  ml/traffic_pipeline.py     synthetic dataset, training, evaluation, inference
  alembic/                   PostgreSQL migrations
  tests/                     unit and end-to-end API tests
```

FastAPI executes synchronous CPU-bound optimization endpoints in its worker thread pool, so the event loop remains available. For multi-user production traffic, run multiple API workers and move expensive QAOA jobs to a durable external worker queue.

## Configuration

See [`backend/.env.example`](backend/.env.example). In production:

- use a unique secret of at least 32 characters;
- enable `COOKIE_SECURE=true` behind HTTPS;
- restrict `CORS_ORIGINS` to the deployed frontend;
- use a dedicated PostgreSQL role;
- set `OSRM_BASE_URL` to a self-hosted OSRM instance for reliable production capacity;
- tune `OSRM_TIMEOUT_SECONDS` for the deployment network;
- run `alembic upgrade head` before the API;
- connect structured process logs to a durable log store.

## Data and research limitations

`ScenarioDataset.generate` creates reproducible, labelled synthetic observations with weather, density, road category, surface, time, historical congestion, and location effects. The UI shows the dataset fingerprint and model holdout metrics. Replace this generator with a versioned real dataset adapter before making claims about real-world prediction accuracy.

The route-selection graph is a compact capstone scenario with 16 Chandigarh-region landmarks and curated directed links. Vehicle, traffic, weather, road quality, time, closures, construction, road width, and objective weights modify additive edge costs and can select different landmark sequences. OSRM then snaps each selected sequence to real roads for map display; OSRM does not provide the synthetic scenario costs. The current dataset does not claim authoritative one-way or turn-restriction coverage. A production rollout should import and version a licensed or OSM-derived road-network snapshot, self-host OSRM, and preserve the same edge contract.
